## 1. 结论与开发就绪判断

- 一句话结论：做本地运行的 A 股热点面板，从开盘啦匿名接口拉数据，自算「情绪温度」，DeepSeek 写点评，产出「题材强度轮动面板 + 情绪温度面板 + 每日点评」三个输出物。
- 是否可以进入开发：**可以**；阻塞项：无。
- 已确认事实：
  - 开盘啦「板块强度」等核心数据可通过老版本匿名接口（`apiv=w42`）直连获取，**免 token、免抓包**（2026-11-14 已实测 `errcode=0`，见 `docs/research-开盘啦数据源调研.md`）。
  - 强度值有正有负：正=走强、负=走弱。
  - 匿名接口不暴露「市场情绪温度计 0–100」，改为自算（已确认）。
- 推断（标来源）：情绪温度自算公式为**本项目自主定义**，非开盘啦原值；强度项中「连板率」接口暂未验证，先用涨停−跌停净差替代。
- 未验证风险：`apiv=w42` 老接口存在被开盘啦下线/收紧风险，需降级预案（AKShare 兜底）。

## 2. 背景、目标与成功标准

- 当前问题：需要一个本地、个人使用的行情观察面板，核心看「板块强度」与「情绪温度」，避免手动盯盘。
- 用户或业务价值：每日盘后一键产出结构化观察结果，替代人工整理。
- 目标行为：`python run.py` 一条命令 → 拉当天数据 → 算温度 → 点评 → 渲染面板，跑完即退、无常驻。
- 可观察成功标准：
  1. 能拉到真实板块强度排名与市场情绪家数并落地 `data/`。
  2. 情绪温度输出 0–100 数值且可解释。
  3. 轮动面板还原样例图（按交易日横向排开、走强红/走弱绿、点题材跨列高亮+底部轮动轨迹）。
  4. 情绪温度面板 + DeepSeek 点评可出。

## 5. 最终业务合同

- 对象与粒度：**板块**（代码+名称+强度+涨跌幅+成交额+主力净额+涨停数）与**市场情绪**（涨跌家数/涨停跌停家数/涨跌比）。
- 输入合同（采集）：
  - 全板块强度排名：`RealRankingInfo`（`c=ZhiShuRanking`，`Order=1&st=30&Index=0&Type=1&ZSType=7&Date=YYYY-MM-DD`），分页拿全。
  - 市场情绪：`MoodNumCount`（`c=MarketMood`）。
  - 公共参数：随机 `DeviceID`(uuid4)、`apiv=w42`、`VerSion=5.21.0.2`，无 token。
- 输出合同：
  - 情绪温度：`0–100` 数值。
  - 轮动面板：每交易日列，走强(强度>0，红)/走弱(强度<0，绿)各 top 15，点题材跨列高亮+底部轮动轨迹。
  - 点评：近 5 日趋势 + 当天的一段文字。
- 情绪温度公式（v1，已确认，参数为可调常量）：

```
广度项 = (上涨家数 − 下跌家数) / (上涨家数 + 下跌家数) × 50      # 范围 −50 ~ +50
强度项 = clamp((涨停数 − 跌停数) × 0.5, −50, +50)               # 连板率暂缺，用净差替代
情绪温度 = clamp(50 + 广度项 + 强度项, 0, 100)
```

- 历史累积：**只拉当天**，`data/` 按日期存快照，逐步累积成序列；轮动面板读已有日期序列。
- 失败与恢复：接口失败打印根因并退出，不写脏数据；DeepSeek 无 key/关停时跳过点评不报错；付费调用先记账、超预算熔断。

## 6. 目标技术设计

- 分层职责：采集（只拉数据）/ 指标（只算温度）/ 点评（只调模型）/ 渲染（只读结果产出网页）/ 存储（只读写快照）。
- 依赖：`requests`（HTTP）、`pyyaml`（配置）。本地存储用 JSON 快照（避免引入数据库）。
- 可观测：采集打印接口状态码与 errcode；点评打印预估 token 数与实际成本。
- 安全：DeepSeek key 放 `config.yaml`（本地，不入库、不提交）。
