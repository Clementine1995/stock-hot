# stock-hot 项目现状与接手说明（HANDOFF）

> 用途：跨机器 / 跨会话接手本项目时快速进入上下文。
> 事实优先级：**代码 > 测试 > 运行现场 > 本文档**。本文档与代码冲突时以代码为准，并同步更新本文档。

## 一、一句话现状

本地 A 股热点面板：从**开盘啦匿名接口**拉板块强度 + 市场情绪家数，**自算情绪温度**，本地 Web 站点多标签展示（题材强度轮动日历墙 / 情绪温度面板 / 数字报表 / 核心票池），页面「刷新数据」按钮更新最近交易日。零第三方依赖，JSON 快照存储。

## 二、数据源（接手必需，最易踩坑处）

### 2.1 开盘啦匿名接口（免 token / 免抓包）

关键结论：开盘啦「板块强度」是私有指标，公开行情源没有；但**老版本匿名接口 `apiv=w42` 免 token 可直接拿**，无需抓包、无需真机、无需模拟器。

| 接口 | 域名 | 说明 |
| --- | --- | --- |
| `RealRankingInfo` | `apphis.longhuvip.com`（历史域） | 板块强度排名，**支持 `Date` 回查历史** |
| `MoodNumCount` | `apphwhq.longhuvip.com`（当日域） | 市场情绪家数，**只返回最新，忽略 `Date`** |
| `HisZhangFuDetail` | `apphis.longhuvip.com`（历史域） | 全市场涨跌/涨停/跌停家数，**支持 `Day` 回查历史**（情绪历史回补用） |
| `ZhiShuStockList_W8` | `apphis.longhuvip.com`（历史域） | 板块完整成分股（`Type=22`），**支持 `Date` 回查**（核心票池用） |

**字段映射**（`RealRankingInfo` 返回 `list[][]`，下标语义）：
- `[0]` 板块代码、`[1]` 名称、`[2]` 强度、`[3]` 涨跌幅%、`[5]` 成交额(元)、`[6]` 主力净额(元)。

**分页铁律**：`st` 必须固定 = 30（改其他值接口返回空），`Index` 为起始偏移、每页 +30 循环直到 `list` 为空。

**错误码**：`errcode=1020` = 非交易日或数据未更新（采集器已处理，返回空列表）。

**市场情绪字段**（`MoodNumCount`）：`SZJS` 上涨家数 / `XDJS` 下跌家数 / `ZTJS` 涨停家数 / `DTJS` 跌停家数 / `bl` 涨跌比（口径待确认，v1 公式未用）。

### 2.2 情绪温度（自算，非真值）

开盘啦「市场情绪温度计 0–100」是私有指标，匿名接口不暴露。现用 `src/indicators/mood.py` 的 v1 公式自算：

```
广度项 = (上涨 − 下跌) / (上涨 + 下跌) × 30        # 约 −30 ~ +30
强度项 = clamp((涨停 − 跌停) × 0.2, ±30)           # 连板率暂缺，用净差替代
温度   = clamp(50 + 广度项 + 强度项, 0, 100)
```

三档：≤40 冰点（绿）、≥60 高温（红）、之间中性（橙）。
系数经 2026-11-17 用 30 个交易日回测标定（初版广度50/强度0.5 导致 8/30 天贴顶贴底，标定后 0 天）。

**历史回查**：`HisZhangFuDetail`（`c=HisHomeDingPan`，历史域 `apphis`，参数 `Day`）支持回查全市场涨跌家数+涨停跌停，口径与 `MoodNumCount` 一致，故历史温度曲线可经 `backfill.py` 回补（`python backfill.py 30 <最近交易日>`）。

## 三、架构分层与目录

依赖方向单向（上层不反向依赖下层）：

```
采集层  src/collectors/   base.py（抽象 Collector）+ kaipanla.py（开盘啦实现）
存储层  src/storage/store.py   快照读写（唯一访问点，迁 SQLite 只改这里）
指标层  src/indicators/mood.py 情绪温度纯函数
展示层  server.py + web/index.html  单页多标签 + 刷新按钮
```

> DeepSeek 点评已接入 `src/llm/review.py`（默认关闭），走「采集→计算→点评」后处理链；`config.local.json`（不入库）填 key 并置 `enabled=true` 启用。

路由（`server.py`）：
- `GET /` → `web/index.html`
- `GET /api/data` → 结构化数据（days / series / mood_series / stats / latest）
- `POST /api/refresh` → 采集最近一个交易日（可选 `?date=`）落快照

## 四、关键决策记录（为何这么做）

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 数据源用匿名接口，不抓包 | 实测 `apiv=w42` 免 token 直接拿板块强度真值，比 mitmproxy 抓包省大量维护 |
| 2 | 情绪温度自算（方案 A），不抓包真值 | 为单个「温度计 0–100」搭抓包环境代价大收益小；原料同源 |
| 3 | 历史回补 10 个交易日 | 用户样例图是日历墙多日，接口支持 `Date` 回查；已回补 11-13→11-02 |
| 4 | 本地常驻网站 + 刷新按钮（非定时） | 用户先选「手动触发」，后质疑「太简单」升级为网站，仍不要定时 |
| 5 | 零第三方依赖 | 避开「装依赖需授权」红线，任何 Python 3 环境可跑 |
| 6 | 走强/走弱按强度正负切，各 top 15 | 用户确认；正=走强(红)、负=走弱(绿) |
| 7 | `data/` 与 `output/` 均不进 git | 板块强度与情绪现均可经接口历史回查（`HisZhangFuDetail`），快照可再生，另一台电脑 `backfill.py` 重拉即可 |
